# 2. 내 저장소에 쌓기

<Callout type="tip" emoji="👀">
이 단계는 선택입니다. 오늘은 제가 화면으로 보여드리고, 원하시는 분은 이 문서를 그대로 따라 집에서 해보셔도 좋습니다. 30분 뒤 `https://내아이디.github.io/ai-newsletter/`에 내 1호가 떠 있고, 내일 08:00에 2호가 자동으로 추가되도록 예약돼 있으면 성공입니다.
</Callout>

## ![질문](/illustrations/question.png) 왜 아티팩트로 끝내지 않는가

1단계에서 만든 아티팩트 링크는 그 순간엔 완벽합니다. 그런데 내일 3호, 모레 4호가 오면 어떻게 될까요? 이메일함을 뒤져 어제 링크를 찾아야 하고, 두 달 뒤 "그때 봤던 그 소식"을 다시 찾으려면 방법이 없습니다. 아티팩트 링크는 한 호 한 호가 따로 떠다니는 낱장입니다.

저장소는 그 낱장을 한곳에 묶어주는 바인더입니다. 오늘 호가 파일 하나로 남고, 내일 호가 그 옆에 쌓이고, 목록 페이지가 전체를 훑어보게 해줍니다. 3호를 받을 때쯤이면 "지난주에 뭐 있었지?"를 내 주소 하나로 다시 열어볼 수 있습니다. 이게 아카이빙입니다.

<Callout type="note" emoji={<img src="/illustrations/dev.png" alt="" width="32" height="32" />}>
**GitHub이 뭔가요?** 파일을 인터넷에 올려두고, 바뀐 기록을 전부 남겨주는 저장 서비스입니다. 워드 파일을 구글 드라이브에 올리는 것과 비슷하지만, 한 가지가 다릅니다. 파일이 바뀔 때마다 "몇 월 며칠 무엇이 바뀌었는지"가 전부 남아서, 예전 버전으로 되돌리거나 언제 뭐가 추가됐는지 나중에 확인할 수 있습니다. 오늘은 이 저장 공간에 뉴스레터 파일을 매일 하나씩 쌓습니다.

<Screenshot
  src="/screenshots/repo-editions.png"
  alt="GitHub 저장소의 editions 폴더 화면. 날짜별 HTML 파일이 나열되고, 오른쪽에 각 파일의 마지막 커밋 메시지와 날짜가 보인다"
  caption="파일마다 언제·무엇이 바뀌었는지가 오른쪽에 그대로 남습니다."
/>
</Callout>

**데이터가 쌓이는 구조**는 세 칸이면 끝납니다.

<Flow>
  <FlowStep label="①" title="오늘 만든 아티팩트" icon="/illustrations/ai-write.png">
    Cowork가 만든 한 호. 링크 하나로 떠 있는 낱장입니다.
  </FlowStep>
  <FlowStep label="②" title="저장소에 날짜별 파일로" icon="/illustrations/books.png">
    editions/2026-09-18.html 같은 파일 하나. 내일은 그 옆에 파일이 하나 더 쌓입니다.
  </FlowStep>
  <FlowStep label="③" title="내 주소에서 목록으로" icon="/illustrations/present.png" accent>
    index.html이 쌓인 파일을 전부 나열합니다. 이 주소 하나로 지난 호를 다 봅니다.
  </FlowStep>
</Flow>

이 3단계 구조가 오늘 여러분이 만드는 저장소의 전부입니다. 새 기술을 배우는 게 아니라, 이미 만든 뉴스레터를 "낱장"에서 "쌓이는 파일"로 옮기는 작업입니다.

## ![기어](/illustrations/gears.png) 3 · Pages 켜기

내 저장소에서 **Settings** 탭 → 왼쪽 메뉴 **Pages** → Build and deployment.

1. Source: **Deploy from a branch**
2. Branch: **main**, 폴더: **/ (root)**
3. **Save**

1~2분 기다리면 위쪽에 `https://내아이디.github.io/ai-newsletter/` 주소가 나타납니다. 눌러봅니다.

## ![연결](/illustrations/team.png) 4 · Cowork에 GitHub 커넥터 연결

GitHub은 Gmail처럼 인기 목록에 카드로 없습니다. GitHub 공식 원격 서버 주소를 "사용자 지정 커넥터"로 등록해야 하는데, 이 등록을 Cowork에게 말로 시킵니다. 아직 안 했다면 지금 이 문장을 붙입니다. 화면은 홈 준비물 4번에도 있습니다.

```text
GitHub 공식 원격 MCP 서버(https://api.githubcopilot.com/mcp/)를
사용자 지정 커넥터로 추가해줘. 이름은 GitHub으로.
```

브라우저에 인증 화면이 뜨면 GitHub 계정으로 로그인해 허용합니다. 저장소 접근 범위를 물으면 `ai-newsletter` 하나만 골라도 됩니다.

<Callout type="warning">
여기까지 화면으로 따라오신 것으로 충분합니다. 4번부터는 집에서 이 페이지를 그대로 보고 이어가시면 됩니다.
</Callout>

<Callout type="tip" title="이렇게 보이면 성공">
Cowork 커넥터 목록에 GitHub이 "연결됨"으로 보입니다.
</Callout>

## ![과녁](/illustrations/target.png) 5 · 내 것으로 바꾸기

템플릿에는 진행자의 이름과 관심사가 예시로 들어 있습니다. 파일을 직접 고치는 대신 Cowork에게 말합니다.

```text
GitHub 저장소 {내 아이디}/ai-newsletter 에서 아래를 고치고 커밋해줘.
- AGENT.md의 owner를 "{내 이름}"으로
- AGENT.md의 pages_url을 https://{내 아이디}.github.io/ai-newsletter 로
- AGENT.md의 interests를 아까 정한 관심사 3개로 바꾸고 나머지 탭은 지워줘
- index.html의 "(내 이름)"을 "{내 이름}"으로
다른 파일은 건드리지 마.
```

`AGENT.md`는 관심사와 선정 기준이 적힌 파일입니다. 스케줄이 돌 때마다 이 파일을 읽습니다.

<Callout type="tip" title="이렇게 보이면 성공">
저장소에서 `AGENT.md`를 열면 owner가 내 이름이고, interests에 내 탭 3개만 있습니다.
</Callout>

## ![신문](/illustrations/news.png) 6 · 1호 발행

아까 1단계에서 만든 뉴스레터를 그대로 저장소에 쌓습니다. 새로 검색해도 되지만, 같은 내용이 이제 내 주소에 올라가는 걸 먼저 봅니다.

```text
아까 아티팩트로 만든 뉴스레터 내용을 그대로 써서,
{내 아이디}/ai-newsletter 저장소에 editions/{오늘 날짜}.html 을 만들어줘.
_TEMPLATE_edition.html을 복제해서 NEWSLETTER 데이터만 바꾸고, meta.edition은 Vol.01로.
index.html의 ARCHIVE.editions 맨 앞에 이 호를 추가하고, demo: true 인 예시 항목은 지워줘.
커밋하고 푸시한 뒤 내 Pages 주소를 알려줘.
```

푸시가 끝나면 1~2분 뒤 내 주소를 새로고침합니다.

<Callout type="tip" title="이렇게 보이면 성공">
데모가 사라지고 **내 1호가 목록 맨 위**에 있습니다. 누르면 아까 이메일로 받은 것과 같은 뉴스레터가 열립니다. 이 주소는 휴대폰에서도, 동료에게 보내도 열립니다.
</Callout>

<Toggle title="안에서 무슨 일이 일어나나 (궁금한 분만)">

파일 이름을 알 필요는 없지만, 구조가 궁금하면 이렇게 돼 있습니다.

- 한 호는 `editions/{날짜}.html` 파일 하나입니다. `_TEMPLATE_edition.html`을 복제해 안의 데이터만 채웁니다.
- 지난 호 목록은 `index.html`입니다. 그 안의 목록 맨 앞에 새 호 한 줄이 추가됩니다.
- 관심사·선정 기준·문장 규칙은 `AGENT.md`에 적혀 있습니다. 스케줄이 돌 때마다 이 파일을 읽습니다. 함께 고친 기준도 여기 남겨 다음 호에 반영됩니다.
- 파일을 저장소에 올리면(푸시) GitHub Pages가 1~2분 안에 같은 주소에 새 내용을 보여줍니다. 빌드도 서버도 없습니다.

</Toggle>

## ![캘린더](/illustrations/calendar.png) 7 · 내일 아침 예약

1단계에서 건 예약은 이메일로만 옵니다. 이제 같은 채팅창에서 이어서 말해, 저장소 커밋까지 하도록 예약을 바꿉니다. 새 메뉴는 찾지 않습니다.

```text
아까 건 매일 아침 8시 예약을 이렇게 바꿔줘.
{내 아이디}/ai-newsletter 저장소의 AGENT.md 기준으로 지난 24시간 소식으로 새 호를 만들어
editions/에 커밋·푸시하고, https://{내 아이디}.github.io/ai-newsletter 주소를 {내 이메일}로 보내줘.
과거 호는 건드리지 마. 출처 확인이나 푸시에 실패하면 발행을 멈추고 무엇이 문제인지 알려줘.

이메일 본문은 저장소의 _TEMPLATE_email.html을 채워서 HTML 형식(text/html)으로 보내줘.
태그가 글자로 그대로 보이면 안 돼.
```

1단계를 건너뛰고 여기서 처음 예약을 건다면 "아까 건" 대신 "매일 아침 8시에"로 바꿔 그대로 붙입니다. 매번 직접 확인하고 발행하고 싶으면 "푸시하지 말고 초안만 보내줘"를 추가합니다.

지금 바로 확인하고 싶으면 이어서 붙입니다.

```text
방금 바꾼 예약과 별개로, 지금 테스트로 한 번 실행해서 결과를 보내줘.
```

<Callout type="tip" title="이렇게 보이면 성공">
잠시 뒤 이메일이 오고, 링크를 열면 내 GitHub Pages 주소에 새 호가 올라가 있습니다. 이게 되면 예약도 정상 작동한다는 뜻입니다. 실제로 매일 도는지는 내일 아침 이메일로 다시 확인합니다.
</Callout>

<Toggle title="막혔을 때 (자주 걸리는 지점 6개)">

| 상황 | 해볼 것 |
|---|---|
| Public을 못 골랐다 / Private으로 만들었다 | Settings → General 맨 아래 Change visibility → Public. 무료 계정 Pages는 Public만 됩니다 |
| Pages 주소가 404 | 1~2분 더 기다립니다. Settings → Pages에서 Source가 main / (root)인지 다시 봅니다 |
| 커넥터 인증 팝업이 안 뜬다 | 브라우저 팝업 차단을 해제합니다. 안 되면 오늘은 3번까지, 집에서 이어갑니다 |
| 푸시했는데 화면이 안 바뀐다 | 시크릿 창으로 열거나 1~2분 뒤 새로고침. 저장소 `editions/` 폴더에 오늘 파일이 있는지 봅니다 |
| AI가 다른 저장소에 썼다 | 프롬프트에 `{내 아이디}/ai-newsletter`가 정확히 들어갔는지 확인하고 다시 붙입니다 |
| 예약 메뉴를 못 찾는다 | 진행자 화면으로 위치를 봅니다. 못 걸었으면 내 주소와 7번 프롬프트를 적어두고 집에서 합니다 |

</Toggle>
